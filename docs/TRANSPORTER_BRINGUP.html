ClaudeOS · Transporter Bring-Up

Dell Latitude 7280 · testbed install · checkboxes persist in this browser

0Before you leave your desk

  • Flash a NixOS minimal ISO (24.11+ / unstable) to a USB stick.
  • Locate your personal age key (the &user recipient in .sops.yaml) — usually ~/.config/sops/age/keys.txt on an old install or in your backups. Without it you cannot re-encrypt secrets for the new host (Phase 3).
  • Have the rotated UniFi API key handy — it gets added to sops in the same step.
  • Confirm main is green: nix flake check passes both hosts.

1Install (destructive — wipes /dev/sda)

Boot the USB stick on the Latitude (F12 boot menu), then:

# network (ethernet just works; wifi:)
sudo systemctl start wpa_supplicant
wpa_cli   # > add_network / set_network 0 ssid "..." psk "..." / enable_network 0

# get the config (repo is PRIVATE — authenticate first)
sudo -i
# the installer doesn't enable flakes by default — turn them on for this session
export NIX_CONFIG="experimental-features = nix-command flakes"
nix-shell -p gh git
gh auth login   # GitHub.com → HTTPS → "Login with a web browser"
                # prints a short code (e.g. AB12-CD34); enter it at github.com/login/device on your phone
gh repo clone heytcass/claudeos /mnt-config && cd /mnt-config

# partition + format + mount via disko (1G ESP + btrfs subvolumes)
nix run github:nix-community/disko/latest -- \
  --mode destroy,format,mount --flake .#transporter

# install
nixos-install --flake .#transporter
# set the user password before rebooting
nixos-enter --root /mnt -c 'passwd tom'
reboot
⚠ disko erases /dev/sda (pinned in hosts/transporter/default.nix). Unplug any USB storage first so nothing else enumerates as sda.
  • disko ran clean (1G ESP, @ @home @nix @log subvolumes)
  • nixos-install finished; password set; rebooted into GDM

2First login

  • Log into GNOME, connect wifi. Keyboard is colemak (dconf) — TTYs too.
  • Authenticate first (repo is private): gh auth login → GitHub.com → HTTPS → "Login with a web browser" (short code at github.com/login/device — no token typing). This also installs git's credential helper, so auto-update pushes and self-heal PRs work over HTTPS.
  • Clone the repo to its home: gh repo clone heytcass/claudeos ~/.config/claudeos (fish helpers, auto-update, and agents all expect this path)
  • Claude Code self-installs at login (claude-code-installer service). Then: claude login — subscription auth.
  • Sanity: claudeos (help), , cowsay moo (comma), prompt shows ❄ oxidized-ring-baseline after first rebuild.

3Secrets — give this host eyes

# on transporter: derive its age identity
nix shell nixpkgs#ssh-to-age -c sh -c \
  'ssh-to-age < /etc/ssh/ssh_host_ed25519_key.pub'

# on a machine holding your personal age key:
#  1. add the output to .sops.yaml as &transporter_host (key group too)
#  2. add the rotated UniFi key while you're in there:
sops secrets/secrets.yaml        # add: unifi_api_key: <rotated key>
sops updatekeys secrets/secrets.yaml
git commit -am "feat: transporter age recipient + unifi key" && git push

# back on transporter
cd ~/.config/claudeos && git pull && rebuild
  • ls /run/secrets/ shows the jasper_* secrets after rebuild
  • Declare unifi_api_key in modules/common/secrets.nix so fish exports it for the UniFi MCP server

4Wake the organism

  • Timers alive: systemctl --user list-timers → health-check, daily-brief, journal-diary, morning-desk, auto-update
  • Calendar: gcalcli init (OAuth client id/secret now in /run/secrets/) — one browser round-trip
  • Morning Desk: today --refresh → themed dashboard opens in Chrome app mode
  • Constitution: stage a deliberately broken .nix edit in a Claude session and watch the commit get denied
  • Self-heal: break a watched unit on purpose (e.g. point claudeos-journal-diary's ExecStart at a bad path on a branch, rebuild-test, systemctl --user start it) → expect a heal/* PR + notification. Revert after.
  • VM smoke-test gate — first real run: systemctl --user start claudeos-auto-update, then journalctl --user -u claudeos-auto-update -f. Expect: VM builds + boots under KVM, CLAUDEOS-SMOKE-PASS in the journal, commit + push + auto-switch. First live validation of the gate's assumptions: gdm.service goes active without a GPU, kvm-intel module load is tolerated, no stray failed units (sops/snapper/scx are stripped or activation-only in the VM). If red: confirm flake.lock reverted, the notification lists failing units, and claude-heal@claudeos-auto-update fired. Record the verdict in docs/known-issues.md.
  • Headless auth check: systemctl --user start claudeos-daily-brief works without a terminal. If OAuth is flaky from units, wire the API-key lane (sops) — budget already approved, set a $20 console cap.

5The March dealbreakers — the actual point of this machine

Each of these drove the move to Ubuntu. Test deliberately; record verdicts in docs/known-issues.md or a testbed report.

  • File pickers + drag-and-drop — Chrome upload dialogs, dragging files into Slack/Gmail, Nautilus → app drags. GNOME portals should make this boring now.
  • Claude in Chrome — install the extension, run claude --chrome, confirm native-messaging connects reliably across restarts. envfs should fix the FHS script assumptions that broke this.
  • VSCode + Claude extension — install from Marketplace (extensions are mutable now), confirm it survives VSCode updates and rebuilds.
  • Claude desktop app — nix run github:heytcass/claude-desktop-linux-flake — launches, tray works, survives an update cycle.
  • MCP experimentation friction — add a random MCP server to ~/.claude/.mcp.json by hand; no rebuild should be needed (seed-once is working).
All five pass → gti gets reinstalled with confidence. Any fail → it becomes a scoped fix on the testbed, which is exactly what the testbed is for.
